# 概念接地表（Grounding Table）

> 全书概念依赖的地基。写作规则（Grounding）：**每个概念必须先「接地」——读者要么走进来就知道，要么前面某段完整介绍过——后续章节才能直接使用它**。
>
> 本表回答三件事：每个核心概念**在哪章首次接地**、理解它需要**什么前置**、它被**哪些后续章节依赖**。新增或引用概念前先查本表，避免「用了一个前面从没讲过、后面也补不上的词」。
>
> 术语的**唯一定义**见 `content/glossary.md`（一词一义）；本表只管**接地顺序与依赖关系**，两者配合使用。

---

## 一、根概念（全书基石）

这三条在第 1 章「核心循环」首次完整推导，是全书所有章节的公共地基。**任何章节引用它们都算已接地，无需重复解释**；但在第 1 章之前（如第 0 章）只能「预告」，不能当作已知。

| 根概念 | 首次接地 | 一句话 | 被依赖章节 |
|--------|---------|--------|-----------|
| LLM 是无状态函数 | 第 1 章 | `f(messages) → message`：输入一串消息，输出一条消息，不记得上一次调用 | 全部 2–7 章 |
| 消息数组 = agent 状态 | 第 1 章 | 除此之外没有任何「记忆」；历史消息全部喂回 | 全部 2–7 章 |
| 核心循环 = while + 回填 | 第 1 章 | 反复调用 f，把新消息追加到数组末尾再喂回，直到模型不再调工具 | 全部 2–7 章 |

> 第 0 章「引言」已用马具类比 + 伪代码**预告**了「调用模型 → 执行工具 → 回填结果 → 判断结束」四步，但根概念的严格推导（为什么是循环 + 消息数组）只在第 1 章完成。因此第 0 章面向零基础读者时，四步只能当「预告」，不能当「已讲透」。

## 四、Grounding 写作检查清单

写（或改）任何章节时，逐条自检：

- [ ] 本章每个**新概念**都登记进了第二节对应行（接地章节 = 本章），且 `content/glossary.md` 有唯一定义。
- [ ] 本章**引用**的每个概念，其「前置要求」在本章之前已接地；未接地的只能在本章内补接地，不能跳过。
- [ ] 根概念（无状态函数 / 消息数组 = 状态 / 核心循环）只在第 1 章推导一次，后续章节直接引用，**不重复长篇解释**（最多一句「回顾第 1 章」）。
- [ ] 跨章概念（如 Isolate 在第 3 章接地、第 5 章落地）落地处明确标注「回收第 X 章」，而不是当作新概念重新定义。
- [ ] 术语一词一义：与 `content/glossary.md` 冲突的立即消歧，不新造同义异名。
- [ ] 预告 vs 正式接地的边界：第 0 章只许「预告」，不把后续章节的概念当作已知。
