## 动机：为什么需要 harness

你可能遇到过这种情况：你让大模型「帮我修一下这个 bug」，它认真地回了一段文字——告诉你去改哪个文件、怎么改、改完怎么测。但**它自己不会去改文件，不会跑测试，也不会看报错**。

大模型本质上是「会说话的」，不是「会干活的」。它只能生成文字，不能执行动作。

**harness 就是把大模型从「会说话」变成「会干活」的那层框架。**

这影响两类人：

- **个人开发**：你装个 Claude Code / opencode / Codex，它就能直接读你的代码、改文件、跑命令、看报错，而不是只给你文字建议。
- **云端 agent**：像 openclaw、qwen-audio-agent 这样的线上服务，要同时服务海量用户，harness 决定了它能不能稳定、安全、低成本地跑。

一句话：**大家用 LLM 效率不高，往往不是模型不够强，而是没用好 harness 这层。**

## 直觉层：什么是 harness

「harness」本义是**马具 / 缰绳**——套在马身上的那套装备。

一匹好马力量很大，但你直接骑上去，它不会听你的、还可能把你甩下来。你需要缰绳、马鞍、马镫，才能把它的力气变成**可控的、朝你要的方向的拉力**。

大模型就是那匹马：

| 马 | 大模型 |
|----|--------|
| 力量大 | 能力强大（会写代码、会推理） |
| 不会自己干活 | 只会生成文字，不会执行 |
| 需要缰绳驾驭 | 需要 harness 套起来驾驭 |

所以这本书讲的，就是**怎么给大模型套上缰绳**——消息循环、工具调用、上下文管理、沙箱、多 agent 编排……一层层加装，直到它能稳定地替你干活。

## 机制层：一个最小 harness 长什么样

抛开所有复杂概念，一个最小的 harness 核心只有十几行伪代码——一个循环：

```text
messages = [系统提示词, 你的请求]

while 还没结束:
    reply = 大模型(messages)          # ① 让模型生成下一步
    if reply 里要求调用工具:
        result = 执行工具(reply.工具)  # ② 真正执行动作
        messages.append(result)        # ③ 把结果喂回模型
    else:
        return reply                   # ④ 没有工具要调，结束
```

这四步就是所有 agent 的「心跳」：

1. **调用模型**——让模型决定下一步该说什么、该调什么工具
2. **执行工具**——真正去改文件、跑命令、查数据
3. **回填结果**——把执行结果放回对话，让模型「看到」发生了什么
4. **判断结束**——模型不再要求调工具，任务完成

<DiagramFrame src="/diagram/loop/agent-loop.html" title="Agent 核心循环（可交互）" />

真实 harness（opencode / Codex / Claude Code）都在这个循环之上，加装了工具系统、上下文管理、沙箱、多 agent 协作、评测可观测等能力——这正是本书后面八章要逐一拆开的东西。

## 源码层：真实 harness 的骨架

一个真实 harness 的骨架，通常长这样（以 opencode 这类开源项目为例）：

```text
src/
├── loop/        # 上面的消息循环：驱动 agent 反复「调用模型 → 执行 → 回填」
├── tools/       # 工具系统：定义、执行、结果回传
├── context/     # 上下文管理：塞什么进模型、什么时候压缩
├── session/     # 会话状态：一轮对话的完整生命周期
└── transport/   # 与模型 API 通信
```

对比那十几行伪代码，你会发现：**核心循环没变，但每一环都变成了一个子系统**。本书的结构，就是按这个骨架展开——从「核心循环」出发，逐步加装「工具调用」「上下文与记忆」「沙箱与安全」「多 agent 编排」，最后到「评测与可观测」「前沿与生产」和「训练与部署闭环」。

## 时间简史：harness 的来龙去脉

<DiagramFrame src="/diagram/intro/harness-timeline.html" title="Agent Harness 时间简史（可交互）" />

这本书讲 harness，但 harness 不是凭空出现的——它跟着模型一起长大。把时间线摊开，你会看到一条主线：**模型越强，越需要脚手架驾驭**。

### 模型层三分天下

三家硅谷大厂一边把前沿模型往前推，一边都在做自己的 harness——因为它们都意识到：**光有模型不够，得配脚手架才能干活**。

- **Anthropic**：Claude 5.5 系列（Opus / Sonnet / Haiku），2024 年提出 [MCP](https://modelcontextprotocol.io)（工具生态标准化），2026 年提交 IPO 申请（S-1）。它的 harness 是 [Claude Code](https://github.com/anthropics/claude-code)——闭源，但 2026 年 3 月源码泄露，51 万行 TypeScript 被整个社区拆解还原。
- **OpenAI**：[Codex](https://github.com/openai/codex)——本地 CLI、IDE 集成、云端 Codex Web，三形态覆盖。
- **Google**：2026 年 10 月开源 [Harness²](https://github.com/google-research/harness2)——论文直接把「harness」写进标题，后面 RSI 部分细讲。

### harness 层涌现：从「写死」到「可插拔」

早期 harness 跟着具体产品走（Claude Code 属于 Anthropic、Codex 属于 OpenAI）。真正的转折是**开源 harness 大爆发**：

| 项目 | 出品 | star（2026-10） | 一句话 |
|---|---|---|---|
| [OpenClaw](https://github.com/openclaw/openclaw) | openclaw | 39 万+ | 登顶 GitHub（超 Linux） |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | deepseek-ai | 26 万+ | Everything is a Plugin |
| [Hermes Agent](https://github.com/NousResearch/hermes-agent) | Nous Research | 25 万+ | self-improving agent |
| [Claude Code](https://github.com/anthropics/claude-code) | anthropics | 15 万+ | 源码泄露被社区还原 |
| [Codex CLI](https://github.com/openai/codex) / [OpenCode](https://github.com/sst/opencode) / [Pi](https://github.com/earendil-works/pi) | — | — | 开源极简 |

两个信号特别关键：

1. **DeepSeek Harness 的「Everything is a Plugin」**：harness 开始**模块化**——循环、工具、上下文都是插件，可换。
2. **Pi 的「minimal, extensible」**：故意不做 subagent / plan mode，把能力交给 extensions / skills——**harness 从「大而全」转向「小而可扩展」**。

（这两个趋势，第 5 章多 agent、第 7 章前沿会再展开。）

### openclaw：从单机工具长成云端基础设施

2025 年 11 月，奥地利开发者 Peter Steinberger 发起 [OpenClaw](https://github.com/openclaw/openclaw)。到 2026 年，它登顶 GitHub。

它的设计点破了「生产化」的本质——**One Gateway**：

> 同一个 harness，个人笔记本上跑是个人助手，团队部署是共享服务，**唯一区别是配置**。

更关键的是它的架构宣言：**「Models and agent harnesses are plugins you can swap」**——**模型和 harness 彻底解耦**。这正是「agent = LLM + harness」的工程化体现：模型是马，harness 是缰绳，两样都能换。

OpenClaw 由独立非营利 **OpenClaw Foundation（501(c)(3)）** 托管，没有付费墙。2026 年 9 月，Meta 的个人 agent **Muse** 被发现复用了 OpenClaw 内核——社区调侃「Muse is literally OpenClaw for normies」。

### personal agent：从「编码助手」到「通用个人 agent」

时间线推进到当下，harness 的主战场正在从「写代码」转向「当你的个人 agent」：

- [Hermes Agent](https://github.com/NousResearch/hermes-agent)（25.8 万 star）自称 **「The agent that grows with you」**——跨 session 构建对你的理解，从经验里长出新技能。
- **Muse**（Meta）：把 OpenClaw 内核包装成面向普通人的产品。
- [durable-harness](https://github.com/vercel-labs/durable-harness)（Vercel Labs，2026-10）：让 agent 会话变成**可恢复的 workflow**——崩溃后从日志接着跑，不重复执行。

### RSI 闭环：harness 开始「自我进化」

最后一段，也是本书命题的收口——**递归自我改进（RSI）**。

传统上，想让 agent 变强就换更强的模型。但 2026 年的几项工作把方向掉了个头：**冻结模型权重，让 harness 自己进化**：

- [**Harness²**](https://github.com/google-research/harness2)（Google Research，2026-10，[arXiv:2610.14224](https://arxiv.org/abs/2610.14224)）：开篇公式就是 **Agent = Model + Harness**。它把 harness 拆成 8 类可编辑组件（system prompt、guardrails、记忆、工具说明、subagent、skills、scripts、plugin），用「对比行为差异」而非「比分数」来指导自我改进——单步把 GLM-5 在 WorkBuddy-Bench 拉高 11.5 分。
- **RRSI**（谷歌云 × 斯坦福 × UNC）：把 agent 写成 **「固定模型 π + 可演化框架 H」**，并指出自我改进会过拟合，需要正则化。
- **ModularRSI**（北航参与）：明确提出 **Harness RSI**——「模型始终冻结，harness 随执行经验变化」。
- [**Hermes Agent**](https://github.com/NousResearch/hermes-agent)：README 明写 **trajectory 回灌训练下一代 tool-calling 模型**——这就是闭环的最后一环。

国内这条线上，复旦的 [OpenMOSS](https://github.com/OpenMOSS) 在做 LLM 强化学习后训练（如 BandPO 算法）；而「Harness RSI」走的是另一条路——**不动模型，动脚手架**。两条路合起来，就是完整的 RSI 全景。

### 收束：agent = LLM + harness

把时间线串起来，就得到本书的核心命题：

> **agent = LLM + harness**——模型是「会说话的」，harness 是把它变成「会干活的」的那层脚手架。模型越强，越需要脚手架驾驭；而 RSI 又把 harness 产出的 trajectory 回灌训练，让两者互相成就，形成闭环。

后面八章，就是把这个「+ harness」逐层拆开：循环（第 1 章）、工具（第 2 章）、上下文（第 3 章）、沙箱（第 4 章）、多 agent（第 5 章）、评测（第 6 章）、前沿（第 7 章）、训练部署闭环（第 8 章）。

## 小结

- harness 是**把大模型变成 agent 的框架**，核心是一个「调用模型 → 执行工具 → 回填结果」的消息循环。
- 大模型只会生成文字，**不会执行**；harness 让它能改文件、跑命令、查数据。
- 个人开发和云端 agent 的效率，都取决于 harness 这层做得好不好。
- 本书严格基于**真实主流 harness 源码**（opencode / Codex / Claude Code 等）讲解，由浅入深。
- 本书命题是 **agent = LLM + harness**：不仅讲 harness 本体，还贯通它的上游（算法）与下游（推理部署、训练闭环）。
