## 动机：从「个人工具」到「基础设施」

前面七章，我们讲的都是「一个 agent 干一件事」的核心机制。但真实世界里的 agent 有两种更复杂的形态：

- **多模态**：不只有文字，还有语音、图像——像 qwen-audio-agent 这样的实时语音 agent。
- **云端生产化**：从你本地的单进程 harness，变成服务百万用户的分布式系统——像 xiaoaiclaw、coro 这样的线上服务。

这一章看这两个「前沿」形态，并做一次全书的全景回顾。

## 直觉层：同一套骨架，两种「长大」方式

我们反复强调：**核心循环是所有 agent 的共同骨架**。前沿形态不是推翻骨架，而是两种「长大」方式：

- **多模态** = 给这个循环**换输入输出**——不是打字，而是说话、看东西。循环不变，进出通道变了。
- **生产化** = 把这个循环**拆开、放大**——从单进程的一个函数，变成多个独立服务，各自扛住海量请求。循环不变，规模变了。

## 机制层：多模态的「Agent Presence」

语音 agent 和文字 agent 有个本质区别：**文字可以等，语音不能**。

你打字问问题，agent 查资料卡 10 秒，你能接受。但你**说话**问问题，agent 沉默 10 秒，你会以为它坏了。qwen-audio-agent 的核心设计就是解决这个，他们称之为 **Agent Presence**：

> Conversation should keep flowing, and the Agent should always be present. 对话要一直流动，agent 要始终在场。

这意味着语音 agent 的循环里，要插入「填充」机制：agent 查找资料时，不是沉默，而是发出「嗯，我在查」的语音占位——**用流畅的在场感，掩盖后台的思考延迟**。核心循环没变，但「调用模型」和「执行工具」之间多了一层实时交互的缓冲。

## 源码层：corojaw 的生产化模块拆分

看云端生产化。corojaw（Java）把一个 harness 拆成了清晰的模块，每个模块对应我们前面讲过的一章：

| corojaw 模块 | 对应本书章节 | 职责 |
|-------------|-------------|------|
| `corojaw-gateway` | — | 入口网关，接请求、路由 |
| `corojaw-loop` | 第 2 章 核心循环 | 消息循环：调用模型 → 执行工具 → 回填 |
| `corojaw-model` | 第 3 章 工具调用 | 模型接入、工具执行 |
| `corojaw-session` | 第 4 章 上下文 | 会话状态、上下文管理 |
| `corojaw-tool` | 第 5 章 沙箱 | 工具系统 |
| `corojaw-context` | 第 4 章 | 上下文工程 |
| `corojaw-proto` | — | 模块间通信协议（gRPC） |

你会发现一件美妙的事：**我们第二章那个 `runLoop` 函数，在生产化后就是 `corojaw-loop` 一个独立服务**。核心没变，只是从「单进程里的一个函数」变成了「可独立扩展、独立部署的服务」。

这是「从单机到云端」的本质：**不是重写，是拆解 + 放大**。

## 全景横评：一本书看过的所有 harness

回顾全书的主案例，它们在同一套骨架上，各有侧重：

| 项目 | 语言 | 本书用它讲什么 | 最突出的设计 |
|------|------|--------------|-------------|
| opencode | TS | 核心循环、多 agent | 简洁的消息循环 |
| codex | Rust | 工具调用、沙箱 | 真隔离沙箱 + approval mode |
| cc（Claude Code） | TS（还原） | 上下文、记忆 | 五级压缩 + 四层记忆 + Prompt 即编排 |
| pi | TS | 循环、工具、权限 | `beforeToolCall` 权限钩子 |
| deepseek-harness | TS | 评测 | 按用户路径的 benchmark 体系 |
| qwen-audio-agent | TS | 多模态 | Agent Presence |
| corojaw | Java | 生产化 | 模块化微服务拆分 |

这张表就是这本书的地图：**从「一个循环」出发，每一章给这个循环加装一种能力，最后长成能服务百万用户的系统。**

## 小结

- 前沿形态不是推翻核心循环，而是**换进出通道**（多模态）和**拆开放大**（生产化）。
- 多模态语音 agent 的核心挑战是 **Agent Presence**——用流畅在场感掩盖后台延迟。
- 生产化 = 把单进程的循环拆成**独立服务模块**（loop/model/session/tool...），核心不变，规模变大。
- 全书的 harness 在同一套骨架上各有侧重——这就是 agent harness 的完整图景。
