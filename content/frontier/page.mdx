## 动机：从「个人工具」到「基础设施」

前面六章，我们讲的都是「一个单进程里的 agent」。但真实世界里的 agent 有两种更复杂的形态：

- **多模态**：不只有文字，还有语音、图像——像 qwen-audio-agent 这样的实时语音 agent。
- **云端生产化**：从你本地的单进程 harness，变成服务百万用户的分布式系统——像 xiaoaiclaw、coro。

这一章看这两个「前沿」形态，并做一次全书的全景回顾。

## 直觉层：同一套骨架，两种「长大」方式

我们反复强调：**核心循环是所有 agent 的共同骨架**。前沿形态不是推翻骨架，而是两种「长大」方式：

- **多模态** = 给循环**换进出通道**——不是打字，而是说话、看东西。循环不变，进出变了。
- **生产化** = 把循环**拆开、放大**——从单进程一个函数，变成多个独立服务，各自扛住海量请求。循环不变，规模变了。

## 根源理解：核心循环从没变过

回到 step-01 的结论：**LLM 是无状态函数，agent 的状态是消息数组，循环是「反复调用 + 回填」**。

这个结论和「文字还是语音」「单机还是云端」**无关**：

1. **多模态**：语音 agent 也是「消息数组 + 循环」，只是消息从「文本」变成了「音频转录的文本」。核心循环一行不用改。
2. **生产化**：云端 harness 拆成 loop/tool/context 多个服务，但每个服务的核心还是一个「消息循环」。拆的是「部署边界」，不是「循环逻辑」。

所以前沿形态的本质是：**核心循环不变，变的是 I/O 通道和部署规模**。

## 从零实现：模块化拆分

前面六章，我们把循环、工具、上下文、沙箱都写在一个文件里。生产化要做的第一件事，就是**拆成模块**：

```ts
// 单文件 → 多模块（每个模块对应一个生产化服务）
type LoopModule    = { run: (request: string) => Promise<string> };
type ToolsModule   = { list: () => string[]; execute: (name, args) => Promise<string> };
type ContextModule = { estimateTokens: (msgs) => number; compact: (msgs) => Promise<unknown[]> };
type SandboxModule = { check: (toolName, args) => { allow: boolean; reason?: string } };

// 组装：生产化 harness = 各模块的组合
function createHarness(loop, tools, context, sandbox) {
  return { loop, tools, context, sandbox };
}
```

模块化后，模块间通过**接口**通信，而不是共享一个文件——这是「拆开」的关键：每个模块能独立开发、独立扩展、独立部署。

## 对照基准：corojaw 的模块拆分 + 多模态的 Agent Presence

**生产化对照**：corojaw（Java）把一个 harness 拆成了清晰的模块，每个模块对应我们前面的一章：

| corojaw 模块 | 对应本书章节 |
|-------------|-------------|
| `corojaw-loop` | 第 1 章 核心循环 |
| `corojaw-tool` | 第 2 章 工具调用 |
| `corojaw-context` / `corojaw-session` | 第 3 章 上下文 |
| `corojaw-gateway` / `corojaw-proto` | 入口 + 模块通信 |

你会发现：**我们第 1 章那个 `runLoop` 函数，生产化后就是 `corojaw-loop` 一个独立服务**。核心没变，只是从「单进程函数」变成了「可独立扩展的服务」。

**多模态对照**：qwen-audio-agent 是实时语音 agent，核心设计是 **Agent Presence**：

> Conversation should keep flowing, and the Agent should always be present. 对话要一直流动，agent 要始终在场。

语音场景下，agent 查资料卡 10 秒，用户会以为它坏了。所以语音 agent 的循环里要插入「填充」机制：查找时发出「嗯，我在查」的语音占位——**用流畅的在场感，掩盖后台的思考延迟**。核心循环没变，但「调用模型」和「执行工具」之间多了一层实时交互缓冲。

## 小结

- 前沿形态不是推翻核心循环，而是**换进出通道**（多模态）和**拆开放大**（生产化）。
- 多模态的核心挑战是 **Agent Presence**——用流畅在场感掩盖后台延迟。
- 生产化 = 把单进程循环拆成**独立模块**（loop/tool/context/sandbox），核心不变，规模变大。
- 全书的 harness 在同一套骨架上各有侧重——这就是 agent harness 的完整图景。
